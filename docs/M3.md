# M3 specification — history and robustness

M3 adds project **history** (versions, diff view, restore with undo), storage housekeeping (blob garbage collection,
retention, oversized-document rebuild with a recovery dialog), an admin storage page, and a randomized crash test of
the sync layer.

Decision (2026-11-18): **own versioning, not git** — content-addressed snapshots in SQLite + the blob store. A git
export/bridge can be built on top later (PLAN §10/§11). The contract is `packages/shared/src/api.ts` (sections marked
M3). `docs/M1.md` and `docs/M2.md` still apply; where they differ, **this file wins for M3**.

**Done when** (PLAN §9): the property test passes in CI (all clients converge and the persisted text equals the
clients' text, across random edits, disconnects and server kills); a restore can itself be undone; unreferenced blobs
are collected without ever deleting one that is still referenced.

## 1. Versions

**Migration 4** (append to `apps/server/src/db/schema.ts`):

```sql
CREATE TABLE versions (
  id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  kind TEXT NOT NULL CHECK (kind IN ('auto','compile','named','pre_restore','import')),
  label TEXT, created_by TEXT, created_at INTEGER NOT NULL,
  tree_version INTEGER NOT NULL,
  manifest_hash TEXT NOT NULL                     -- sha256 of the sorted (path, file_id, hash) list: dedupe
);
CREATE INDEX versions_project ON versions(project_id, created_at DESC);
CREATE TABLE version_files (
  version_id TEXT NOT NULL REFERENCES versions(id) ON DELETE CASCADE,
  path TEXT NOT NULL, file_id TEXT NOT NULL, kind TEXT NOT NULL CHECK (kind IN ('text','binary')),
  blob_hash TEXT NOT NULL, size INTEGER NOT NULL,
  PRIMARY KEY (version_id, path));
CREATE INDEX version_files_blob ON version_files(blob_hash);
CREATE TABLE version_authors (
  version_id TEXT NOT NULL REFERENCES versions(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL, PRIMARY KEY (version_id, user_id));
ALTER TABLE projects ADD COLUMN dirty_since INTEGER;          -- first unsnapshotted change
ALTER TABLE projects ADD COLUMN last_change_at INTEGER;
CREATE TABLE pending_authors (project_id TEXT NOT NULL, user_id TEXT NOT NULL, PRIMARY KEY (project_id, user_id));
```

**Snapshot** = one synchronous read of every live file (text from the live Y.Doc if loaded, else the compacted text
mirror — the same "snapshot barrier" as compiles), text stored **as a blob** (UTF-8) in the content-addressed blob store
(dedupe: unchanged files cost nothing), binaries by their existing blob hash. Skip creating `auto`/`compile` versions
whose `manifest_hash` equals the latest version's. Record `version_authors` from `pending_authors` (users whose updates
or tree operations happened since the last version; the persistence `update` listener already knows the user id), then
clear them. Clear `dirty_since`. Broadcast `versions-changed`.

**When** (a scheduler tick every 30 s, plus hooks):
- `auto`: a project with `dirty_since` set, when `now - dirty_since ≥ 5 min`; or when the last client leaves the project
  (all its docs and the meta doc unloaded) and it is dirty.
- `compile`: after a `success` build, if the last version is older than 10 min and the manifest changed.
- `named`: `POST /versions` (owner/editor) — always created, even if identical (a label on the same content).
- `pre_restore`: always, immediately before a restore (also when identical: it is the undo point).
- `import`: once, at the end of a zip import.
- The first change to a project that has **no** version yet takes a version of the state *before* that change
  (so history always starts with the original content). For projects that existed before M3, the first scheduler pass
  takes an `auto` version of the current state.

**Retention / thinning** (in the daily GC, configurable): keep every `named`, `pre_restore` and `import` version and
anything with a label; of `auto`/`compile` versions keep all from the last 24 h, the newest per hour for 7 days, the
newest per day for 90 days, the newest per week after that. Never thin the latest version of a project.

## 2. Diff and restore

- `GET …/versions/:id/diff?against=` — see the contract. `current` means the live state (taken through the same snapshot
  function but **not** stored). Content diffs are computed client-side (the web fetches both sides of a file with
  `…/versions/:id/file?path=` or the live raw route) and shown with `@codemirror/merge`.
- **Restore** (`POST …/versions/:id/restore`, owner/editor) — one operation, serialized per project:
  1. Take a `pre_restore` version (label: `Before restoring "<label or date>"`, created_by = caller).
  2. For each file in the version (or only `paths`):
     - the same **file id** is live → move/rename it back to the version's path if needed (respecting name clashes:
       if the target path is taken by another live file, that other file goes to the trash in the same batch);
       text: apply the old text as a **minimal diff** to the live doc (`replaceText`, origin = restore, attributed to
       the caller) — never replace the Y.Doc; binary: set the blob hash.
     - the file id is in the **trash** → restore it from the trash (M2 rules) to the version's path, then as above.
     - the file id no longer exists (purged) → create a new file at that path with that content (new file id).
  3. Whole-project restore only: live files **not** in the version are moved to the trash as **one batch**
     (`deleted_by` = caller) — recoverable from the trash can as well.
  4. Bump `tree_version`, broadcast `tree-changed`, `trash-changed` if needed, `versions-changed` and
     `version-restored` (with `preRestoreVersionId`, so every client can offer **Undo**).
  5. Audit `version.restore`.
- **Undo** = restore the `pre_restore` version. The UI offers it in a toast for 30 s and the version stays in the
  history forever.
- Limits: restoring respects the M1 project limits; a restore that would exceed them fails before changing anything.

## 3. Blob garbage collection and retention (daily, and `POST /api/admin/gc`)

Mark-and-sweep, safe against concurrent uploads:
- **Referenced** = `files.blob_hash` (live **and** trashed) ∪ `version_files.blob_hash` ∪ blobs written in the last
  **24 h** (grace period for in-flight uploads/imports/snapshots that are not committed yet).
- Sweep the blob directory; delete unreferenced files older than the grace period and their `blobs` rows.
- Also: delete `doc_state`/`doc_updates` rows whose doc name refers to no existing file (M2 import crash leftovers);
  purge soft-deleted projects older than 30 days (`PROJECT_RETENTION_DAYS`), including their files, docs, versions,
  builds' outputs; run version thinning (§1); run the trash retention sweep (M2).
- Never runs concurrently with itself; reports a `GcReport` (kept: the last one, shown on the admin page).
- Tests must prove a blob referenced only by an old version, or only by a trashed file, survives, and a blob uploaded
  during the sweep survives.

## 4. Oversized-document rebuild (compaction with epoch bump)

Yjs keeps tombstones, so a document that was heavily rewritten can carry a state much larger than its text.
- During compaction of a doc with **no connected clients**, if `state bytes > max(8 × text bytes, 2 MB)`: rebuild —
  a fresh Y.Doc from the text, `files.epoch += 1` (new doc name), write the new `doc_state`, delete the old doc's rows,
  bump `tree_version`, broadcast `tree-changed`. Audit `doc.rebuild`. Admins can also trigger it for one file
  (`POST /api/admin/files/:fileId/rebuild`, refuses while clients are connected: `409 doc-in-use`).
- A client that still holds the old epoch (offline tab, reconnect) gets `reload-required` from `onAuthenticate`
  (already true since M0).
- **Recovery dialog (web):** on `reload-required` for an open file, if the local doc has unsynced changes
  (`provider.hasUnsyncedChanges` or local text ≠ last synced text), show a dialog *"Your latest changes could not be
  merged automatically"* with a diff of the local text against the server's current text, a **Copy my text** button,
  and **Open the current version**. Without unsynced changes, re-open the file at the new epoch silently.

## 5. Admin storage page

`GET /api/admin/storage` → `StorageReport`, `POST /api/admin/gc` → `GcReport` (admin only, audited). Web: a "Storage"
section on the admin page: totals, per-project table (sortable by size), the last GC report, a **Run GC now** button.

## 6. Property test (the M3 done-criterion)

`apps/server/test/convergence.property.test.ts` with fast-check, against the **real server as a child process**:
- 3 Node clients on one doc (and a second doc for some runs); commands: insert/delete at random positions (including
  concurrent edits at the same spot), disconnect/reconnect a client, pause a client (buffering edits offline) and
  resume, **SIGKILL the server and restart it** on the same data dir, wait random short times.
- After each run: wait for all clients to be synced; assert all clients' texts are identical; start a fresh client and
  assert its text equals them; stop the server **gracefully**, restart, fresh client again equals.
- Invariant for kills: an edit acknowledged by the server and still held by a connected client is never lost.
  (The documented 200 ms buffer window only matters when *every* holder is gone — the test keeps at least one client
  alive across a kill, or waits > 400 ms before killing when it wants a log-only recovery.)
- Bounded so CI stays fast: `numRuns` 25 by default (env `PROPERTY_RUNS` to raise locally), each run < 20 s; on failure
  fast-check's seed and path are printed so the case can be replayed.

## 7. Web

- **History panel** (button "History" in the project top bar): versions newest first, grouped by day, each with kind
  icon, label, time, authors, change counts; "Load more". Filter: "Named only".
- Selecting a version shows its file list with changes against the previous version (toggle: against current);
  clicking a text file opens a side-by-side **merge view** (`@codemirror/merge`, read-only); binary files show
  "changed" and a download link (images: before/after thumbnails).
- Actions: **Name this version** (owner/editor), **Restore this version** (confirm: explains a backup is taken first
  and files not in the version go to the trash), **Restore this file**, **Download as .zip** (zip of that version —
  server route `GET …/versions/:id/export.zip`, same headers as M2 export).
- After any restore (own or a collaborator's, via `version-restored`): toast *"Restored to <label/date> by <name> —
  Undo"* (Undo for owner/editor, 30 s).
- "Name current version" shortcut: a button in the History panel header.
- Recovery dialog (§4) and admin storage page (§5).

## 8. Tests and CI

Unit + e2e for everything above (snapshot dedupe, author attribution, scheduler triggers with a fake clock, thinning
rules, diff matching by id then path incl. renames, restore cases: rename back, from trash, purged → recreate, clash →
trash, binaries, partial restore, undo; GC safety; rebuild + epoch + reload-required; storage report numbers;
migration 4 on an M2 database). The property test runs in the CI `test` job.
