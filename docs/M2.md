# M2 specification — compile loop, trash can, zip

M2 makes the edit → compile → fix loop pleasant and safe: errors in the editor gutter, SyncTeX in both
directions, auto-compile, a **trash can** to restore deleted files, and zip import/export.

The TypeScript contract is `packages/shared/src/api.ts` (sections marked M2). `docs/M1.md` still applies;
where they differ, **this file wins for M2**.

**Done when** (PLAN §9): clicking an error or the PDF lands on the right line; a deleted file or folder can be
restored from the trash can with its content; a malicious zip cannot escape its directory or exhaust the server.

---

## 1. Trash can

Deleted files already stay in the database (M1 soft delete). M2 makes that visible and reversible.

**Migration 3** (append to `apps/server/src/db/schema.ts`):

```sql
ALTER TABLE files ADD COLUMN deleted_by TEXT;          -- user id
ALTER TABLE files ADD COLUMN delete_batch TEXT;        -- uuid shared by everything removed in one deletion
CREATE INDEX files_trash ON files(project_id, delete_batch) WHERE deleted_at IS NOT NULL;
```

Rows deleted before migration 3 (M1) have no batch: treat each such top-level deleted row as its own batch
(top-level = its parent is live, or its parent was deleted at a different time).

**Rules**
- `DELETE /api/projects/:id/files/:fileId` (M1) now also records `deleted_by` and one `delete_batch` for the node and
  all its live descendants, then broadcasts `tree-changed` **and** `trash-changed`.
- **Trash listing** (`GET /api/projects/:id/trash`, any member) returns one `TrashEntry` per batch: the batch's top
  item. Newest first. `originalPath` is computed from the tree as it was at deletion time (the parent chain; if a
  parent has since been purged, use what is known and prefix with `…/`).
- **Restore** (`POST /api/projects/:id/trash/:fileId/restore`, owner/editor, `RestoreRequest`): `fileId` must be the top
  item of a batch (`404 not-found` otherwise). Restores the whole batch in one transaction:
  - Target parent: `parentId` if given (must be a live folder of the project), else the original parent if still live,
    else the root.
  - Name clash with a live sibling (case-insensitive, as in M1) → rename to `name (restored)`, `name (restored 2)`, …,
    inserting the suffix before the extension for files (`main (restored).tex`).
  - Clears `deleted_at`, `deleted_by`, `delete_batch` on the batch. Text files keep their Yjs state (it was compacted on
    delete) and their epoch — no epoch bump needed, because no client can hold a newer state than the server's.
  - Checks the M1 per-project limits (2000 live files, 500 MB binaries) → `413 project-too-large`.
  - Bumps `tree_version`, broadcasts `tree-changed` + `trash-changed`. Audit log `file.restore`.
- **Delete forever** (`DELETE /api/projects/:id/trash/:fileId`, owner/editor): purges the batch — rows, `doc_state`,
  `doc_updates`. Blobs are left for the M3 garbage collector. Broadcasts `trash-changed`. Audit `file.purge`.
- **Empty trash** (`DELETE /api/projects/:id/trash`, owner only): purges every batch. Audit `trash.empty`.
- **Retention:** batches older than **30 days** are purged automatically (sweep at startup and every hour).
  `TrashEntry.expiresAt = deletedAt + 30 days`. Configurable with `TRASH_RETENTION_DAYS`.
- The main file: if a restored file was the project's main file and `main_file_id` is now NULL, set it back.
- Viewers can see the trash (read-only) but not restore or purge.

**UI:** a trash-can button at the bottom of the file tree, with a count badge (`🗑 Trash (3)`). It opens a panel
listing entries (name, original path, who/when deleted, size, "deleted forever in N days") with **Restore**
(optionally "Restore to…" folder picker), **Delete forever** (confirm) and, for owners, **Empty trash** (confirm).
After a restore, the restored item is highlighted in the tree. The delete confirmation in the tree now says
"Move to trash" instead of implying permanence.

## 2. Diagnostics (log parser)

New workspace package **`packages/latex-log-parser`** (MIT, our own code — do not copy Overleaf's AGPL parser):
`parseLatexLog(log: string, opts: { rootDir?: string }): ParsedDiagnostic[]`, pure, no Node APIs.

- Input: the latexmk-driven log as returned by the worker (pdfTeX/XeTeX/LuaTeX), logs are **unwrapped**
  (`max_print_line=10000`, see M1 results), file-line-error style is on.
- Recognise at least: `file:line: message` errors (with the following `l.<n>` context line), `! ` errors without
  file:line, `LaTeX Warning: … on input line N`, `Package <name> Warning: …` (multi-line continuation lines starting
  with `(<name>)`), `Class … Warning`, `LaTeX Font Warning`, `Overfull/Underfull \hbox/\vbox … at lines a--b` /
  `in paragraph at lines`, undefined references and citations (`Reference … undefined`, `Citation … undefined`),
  `There were undefined references`, missing file `! LaTeX Error: File 'x.sty' not found`, and BibTeX/Biber messages
  that latexmk echoes. Emergency stops and "No pages of output" as errors.
- **File attribution** for warnings without `file:line`: track the TeX file stack from `(` / `)` in the log
  (paths start after `(`, may be relative like `./chapters/intro.tex` or absolute into the build dir). Return the
  path relative to `rootDir` when it is inside it; drop TeX Live system paths (they are not project files) and attribute
  to the nearest project file on the stack instead.
- Severity: errors, warnings, and `info` for bad boxes. Deduplicate identical diagnostics. Cap at 500, errors first.
- **Fixtures:** `packages/latex-log-parser/test/fixtures/*.log` generated with real TeX (TinyTeX locally) from small
  documents committed next to them (`*.tex`), covering every pattern above for pdflatex, xelatex and lualatex, plus
  nested `\input` in subfolders. Snapshot-style expected outputs (`*.expected.json`) reviewed by hand.

**Server:** the orchestrator parses each build log (`rootDir` = the build's `src/` directory as it appears in the
log — the worker reports it; if not, strip everything up to and including `/src/`), maps paths to file ids using the
build's path map, and returns `diagnostics` in `BuildResult`. `build.json` stores the result **and** the path map
(`paths: { [path]: fileId }`) and `startedBy`. New route `GET /api/projects/:id/builds/latest`.

**Web:** `@codemirror/lint` diagnostics for the open file (gutter markers + underline on the line; hover shows the
message); a problems list in the log panel ("3 errors, 5 warnings") where clicking an entry opens the file and jumps
to the line. Diagnostics stay attached to the build that produced them; editing shifts them with the text
(map positions through changes) until the next build replaces them.

## 3. SyncTeX

New workspace package **`packages/synctex`** (MIT, our own code): parses a `.synctex.gz` (gunzip'd text) and answers
forward and inverse queries. Pure TypeScript; the caller gunzips.

- `parseSynctex(text: string, limits?): SynctexIndex` — honour `Magnification`, `Unit`, `X Offset`, `Y Offset`;
  inputs (`Input:<tag>:<path>`); pages; records `[` `(` vboxes/hboxes with `h,v:W,H,D`, and the point records
  (`x` kern, `g` glue, `k`, `$` math, `v` void boxes) with their tag/line(/column). Reject inputs over 50 MB unzipped
  (`TooLarge`) and stop at 2M records.
- `view(index, { path, line, column? }): PdfRect[]` — forward search: the boxes of the records whose input is `path`
  and whose line is the smallest line ≥ the requested one that has records (fall back to the closest line before),
  merged per line into per-line rectangles, on the first page that has any. Coordinates converted to PDF points with
  the origin at the top-left of the page.
- `edit(index, { page, x, y }): { path, line, column } | null` — inverse search: the innermost box on that page
  containing the point; else the nearest record by distance; map to its input path and line.
- **Oracle tests:** generate real `.synctex.gz` files with TinyTeX (pdflatex, xelatex, lualatex; multi-file with
  `\input` from a subfolder; two-column; a figure) and compare our answers with the `synctex` command-line tool
  (`synctex view -i line:col:file -o out.pdf`, `synctex edit -o page:x:y:out.pdf`, installed locally via TinyTeX) on
  many sample points: same page, boxes overlapping within a tolerance, same file and line (inverse) for ≥ 95% of
  samples — report the agreement rate; never crash on any input (fuzz the parser with mutated files).

**Server routes** (member, any role; `400` on bad params, `404 not-found` if the build or its synctex file is missing):
`GET …/builds/:buildId/synctex/view?fileId=&line=&column=` and `…/synctex/edit?page=&x=&y=` as in the contract.
Paths in the synctex file are absolute paths of the build's `src/` dir: strip to project-relative and map with the
build's path map; files not in the map (TeX Live files) are never returned by `edit` — fall back to the nearest record
that maps to a project file. Cache the parsed index per build (LRU, 8 builds, bounded by total records).

**Web:** double-click in the PDF → open that file at that line (and flash the line). "Show in PDF" (button above the
editor and `Ctrl+Alt+J`) → scroll the PDF to the boxes and draw a fading highlight. Works only when a PDF from a
successful-or-failed build with synctex output is shown; otherwise the button is disabled with a tooltip.

## 4. Auto-compile and compile limits

- **Web:** an "Auto-compile" toggle next to Recompile (default **on** for editors/owners, stored in `localStorage`
  per project). When on, compile 2.5 s after the last *local* edit, only if no compile is running (the server already
  coalesces). `Ctrl+S` / `Cmd+S` compiles immediately and never triggers the browser's save dialog. Viewers never compile.
- **Server:** per-user compile rate limit (30 per 5 minutes, `429 rate-limited`), and per-instance queue length limit
  (20 waiting builds → `503 compiler-busy`). The existing per-project single-flight stays.
- **Main-file detection** when `main_file_id` is NULL at compile time: `main.tex` at the root; else the only root
  `.tex` containing `\documentclass`; else the first (by path) `.tex` containing `\documentclass`; persist the choice
  and broadcast `project-changed`. If none: `failure` with a clear log line ("No main file: create main.tex or choose
  one in Settings").

## 5. Zip import and export

**Dependency:** `fflate` (MIT, pure JS) in `apps/server` for both directions.

**Export** `GET /api/projects/:id/export.zip` (any member): every live file at its path (text from the live doc if
loaded, else stored text; binaries from the blob store), folders implied by paths, `Content-Disposition: attachment;
filename="<sanitised project name>.zip"`. Stream or build in memory bounded by the project limits (≤ 500 MB + text).

**Import** `POST /api/projects/import?name=<name>` (any logged-in user; body = raw zip, `Content-Length` ≤ 100 MB):
creates a **new** project owned by the caller. Hardening — every rule has a test with a crafted zip:
- Reject (`400 bad-zip` with a message naming the entry) any entry whose name is absolute, contains `..`, a backslash,
  a drive letter, NUL/control characters, or a segment failing `isValidName`; any symlink entry (Unix mode bits in the
  external attributes) or device entry; encrypted entries; duplicate paths, including case-insensitive duplicates and
  a file colliding with a folder.
- Limits: ≤ 2000 entries; ≤ 200 MB total uncompressed; per entry ≤ 50 MB; compression ratio per entry ≤ 200:1 for
  entries over 1 MB; depth ≤ 32; path length ≤ 1024. Enforce **while** inflating (stop as soon as a limit is crossed;
  never trust the sizes declared in the headers). Zip64 accepted only within these limits. Nested zips are stored as
  binary files, never extracted.
- Skip quietly (and report in `ImportReport.skipped`): `__MACOSX/`, `.DS_Store`, `Thumbs.db`, `desktop.ini`, empty
  directories, and LaTeX build artifacts (`*.aux *.log *.out *.toc *.synctex.gz *.fdb_latexmk *.fls *.bbl *.blg`,
  and the PDF named like the main file).
- If every entry sits under one top-level folder, strip it.
- Text/binary classification exactly as uploads (M1 §4). Text docs are seeded by the server.
- Main file detection as in §4; `ImportReport.detectedMainFile`.
- Everything in one transaction + blob writes; on any failure nothing is left behind (no project row, blobs may stay
  for GC).

**UI:** "Import .zip" on the projects page (file picker + name field defaulting to the zip's name); after import, open
the project and show the report (skipped entries) in a dismissible notice. "Download .zip" in the project's menu.

## 6. Tests and CI

- Unit tests for everything above; e2e tests over the real server for trash (delete folder → one trash entry → restore
  with clash rename → content intact in a connected client; purge; empty; retention sweep with a fake clock; viewer
  forbidden), zip (round trip export → import gives identical files; every hostile-zip rule), compile limits,
  main-file detection, diagnostics mapping, SyncTeX routes against a real build.
- New corpus case in `apps/compiler/test/corpus/`? No — zip hardening is server-side; its hostile fixtures live in
  `apps/server/test/fixtures/zips/` (generated by a script in the test, not committed binaries, where possible).
- CI: unchanged jobs; the new packages' tests run in the `test` job (TeX Live 2026 image, which has `synctex`).
