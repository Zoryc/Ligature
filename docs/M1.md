# M1 specification

M1 turns the M0 spike into something a small team can actually use on a server:
real accounts, projects with members and invite links, a full file tree with uploads,
and a CI pipeline that runs the Linux sandbox and the malicious-TeX corpus.

The TypeScript contract is `packages/shared/src/api.ts`. This document is the behaviour around it.
`docs/PLAN.md` §5–§7 is the background; where they differ, **this file wins for M1**.

**Done when** (from PLAN §9): two users on a server co-write and compile a paper with images and a `.bib`;
a viewer cannot edit or compile; every case in the malicious-TeX corpus fails safely (CI, Linux, `uid` sandbox).

---

## 1. Conventions

- All API routes are under `/api`, JSON in and out (except uploads/downloads), session cookie auth.
- Every non-GET request must carry an allowed `Origin` (already enforced in `apps/server/src/http/app.ts`).
- Errors: HTTP status + `{ "error": "<code>", "message"?: "<human text>" }`. Codes used below are part of the contract.
- Request bodies are validated with zod; unknown fields are rejected (`400 bad-request`).
- IDs are UUID v4 (lowercase). Anything else in a path param is `404 not-found`.
- Authorization failures on a project the caller cannot see are `404 not-found` (don't leak existence);
  on a project they can see but lack the role for, `403 forbidden`.
- Every mutation that changes what other clients display broadcasts a `MetaEvent` on `proj/<id>/meta`.

## 2. Accounts

**Usernames, not emails** (decision for M1: no SMTP needed). `username`: 3–32 chars, `^[a-z0-9][a-z0-9._-]*$`,
stored lowercase, unique (case-insensitive). `displayName`: 1–64 chars after trim, no control characters.
**Passwords:** 10–256 chars; argon2id via `@node-rs/argon2` with **explicit** `memoryCost: 19456, timeCost: 2, parallelism: 1`.

**Registration modes** (`instance_settings.registration`, default `invite-only`):

| Mode | Who can sign up |
|---|---|
| `open` | anyone |
| `invite-only` | only with a valid project invite token (they join that project on signup) |
| `closed` | nobody; admins create accounts |

**The very first account** can always sign up (any mode, no invite) and becomes instance admin.
Signup must be race-safe: two concurrent "first" signups must not both become admin (do it in one transaction).

**Routes**

| Route | Who | Notes |
|---|---|---|
| `GET /api/instance` | public | `InstanceInfo` |
| `POST /api/auth/signup` | public | `SignupRequest` → `Me`, sets session cookie. Errors: `registration-closed`, `invite-required`, `invite-invalid`, `username-taken`, `weak-password`, `bad-request` |
| `POST /api/auth/login` | public | `LoginRequest` → `Me`, sets cookie. Wrong user or password: `401 invalid-credentials` (same response and similar timing for both — hash a dummy password when the user doesn't exist). Disabled user: `403 account-disabled`. Rate limit → `429 rate-limited` |
| `POST /api/auth/logout` | session | deletes the session row and the cookie |
| `GET /api/me` | session | `Me` |
| `PATCH /api/me` | session | `UpdateMeRequest` → `Me` |
| `POST /api/me/password` | session | `ChangePasswordRequest`; wrong current → `403 invalid-credentials`; deletes **all other** sessions of that user |
| `GET /api/admin/users` | admin | `AdminUser[]` |
| `POST /api/admin/users` | admin | `AdminCreateUserRequest` → `AdminUser` |
| `PATCH /api/admin/users/:id` | admin | `AdminUpdateUserRequest`. Disabling a user or setting a password deletes all their sessions and closes their sockets. An admin cannot remove their own admin flag or disable themselves (`409 last-admin` if it would leave zero active admins). |
| `GET /api/admin/settings` / `PATCH` | admin | `InstanceSettings` |

**Rate limiting** (in memory is fine for M1): login — 10 failures per 15 min per (IP, username) and 50 per 15 min per IP;
signup and invite preview — 20 per 15 min per IP. Use the socket's remote address (no proxy headers unless
`TRUST_PROXY=1`, then the first `X-Forwarded-For` hop).

**Sessions:** unchanged from M0 (sha256 of a 32-byte token, HttpOnly, SameSite=Lax, Secure in production),
30-day expiry, **sliding**: `expires_at` is pushed forward at most once per hour on use. Disabled users' sessions are invalid.

**Dev login** (`POST /api/dev/login`) stays, development only, and dev seeding stays (alice/bob/carol get the
password `ligature-dev-password` so they can also use the normal login form). In production neither exists.

## 3. Projects and members

**Exactly one owner per project** (PLAN §5). Roles: owner > editor > viewer (see `packages/shared/src/roles.ts`).

| Route | Who | Notes |
|---|---|---|
| `GET /api/projects` | session | `ProjectSummary[]` (non-deleted, where caller is a member), most recently updated first |
| `POST /api/projects` | session | `CreateProjectRequest` (name 1–120 chars) → `ProjectDetail`. Creates the root row and a `main.tex` from a minimal article template; caller is owner; `main_file_id` set |
| `GET /api/projects/:id` | member | `ProjectDetail` |
| `PATCH /api/projects/:id` | see contract | `UpdateProjectRequest`; `mainFileId` must be a live **text** file of this project ending in `.tex`; broadcasts `project-changed` |
| `DELETE /api/projects/:id` | owner | soft delete (`deleted_at`); broadcasts `project-deleted`, then closes all sockets of the project |
| `GET /api/projects/:id/members` | member | `Member[]` |
| `PATCH /api/projects/:id/members/:userId` | owner | `UpdateMemberRequest`; cannot target self (`409 owner-immutable`) |
| `DELETE /api/projects/:id/members/:userId` | owner, or the member themself (leave) | the owner cannot leave (`409 owner-must-transfer`) |
| `POST /api/projects/:id/transfer` | owner | `TransferOwnershipRequest`; target must already be a member; old owner becomes editor |
| `POST /api/projects/:id/invites` | owner | `CreateInviteRequest` → `CreatedInvite` (default expiry 168 h, max 720 h; maxUses null = unlimited, else 1–1000) |
| `GET /api/projects/:id/invites` | owner | active invites (not revoked, not expired, not used up) |
| `DELETE /api/projects/:id/invites/:inviteId` | owner | revoke |
| `GET /api/invites/:token` | public | `InvitePreview`, or `404 invite-invalid` for unknown/expired/revoked/used-up |
| `POST /api/invites/:token/accept` | session | joins with the invite's role and increments `uses` atomically; if already a member, keep the **higher** of the two roles and don't consume a use |

**Revocation is immediate.** Whenever a member is removed, their role changes, a project is deleted, or a user is
disabled, the server closes that user's Hocuspocus connections to the affected project(s)
(`connection.close()` on connections whose `context.user.id` matches), and broadcasts `access-revoked` /
`members-changed`. On reconnect `onAuthenticate` re-reads the role (a demoted editor comes back read-only).

`onAuthenticate` must also reject deleted projects and disabled users.

## 4. File tree

Rules (server-enforced; names validated with `isValidName` from `@ligature/shared`):

- Every operation runs in **one SQLite transaction**, increments `projects.tree_version`, updates `projects.updated_at`,
  then broadcasts `tree-changed`.
- The root row cannot be renamed, moved or deleted. Names are unique among live siblings
  (`409 name-taken`). Moving a folder into itself or a descendant → `409 cycle`. Target parent must be a live folder of the same project.
- Max depth 32 and total path length 1024 (same limits as the compiler; build the full path and check `isValidRelPath`).
- Per-project limits: 2000 live files, 500 MB of live binary content (`413 project-too-large`).
- **Delete** is a soft delete (`deleted_at`) of the node and, for folders, all live descendants. For each deleted text file:
  compact + unload its doc, close its connections with reason `file-deleted`, refuse future auth for it (already true: `deleted_at` check).
  If the deleted file was the main file, `main_file_id` becomes NULL.
- Renames/moves never touch the Yjs doc (paths are not part of doc names).

**Text vs binary.** A file is *text* iff its extension is in the allowlist
`.tex .bib .sty .cls .bst .bbx .cbx .dtx .ins .txt .md .csv .tsv .dat .tikz .pgf .lua .cfg .def .clo .fd .ist .gst .bbl`
**and** the bytes are valid UTF-8 (BOM stripped) **and** ≤ 1 MB. Everything else is *binary*. Creating a *text* file
through `POST /files` with a non-allowlisted extension is allowed (users may want `notes.txt`-like names); uploads use the rule above.

| Route | Who | Notes |
|---|---|---|
| `POST /api/projects/:id/files` | owner/editor | `CreateFileRequest` → `TreeEntry`; text content seeded by the server (`DocStore.seed`), ≤ 1 MB |
| `PATCH /api/projects/:id/files/:fileId` | owner/editor | `UpdateFileRequest` → `TreeEntry` |
| `DELETE /api/projects/:id/files/:fileId` | owner/editor | soft delete (recursive) |
| `POST /api/projects/:id/upload?parentId=&name=` | owner/editor | raw body, `Content-Length` required, max 50 MB (`413 too-large`); see `UploadResponse` doc in the contract |
| `GET /api/projects/:id/files/:fileId/raw` | member | text: current live text (or stored text if not loaded); binary: blob bytes. Headers: `Content-Disposition: attachment` unless `?inline=1` **and** the type is an image other than SVG (`png jpg jpeg gif webp`); `X-Content-Type-Options: nosniff`; `Content-Security-Policy: default-src 'none'; sandbox` |

**Blob store:** `DATA_DIR/blobs/ab/cdef…` (sha256). Write to a temp file in the same directory, fsync, rename.
Record in a `blobs(hash PK, size, created_at)` table. No GC in M1 (M3).

**Server-originated text edits** (upload replacing a text file): compute a minimal diff with `fast-diff`
between the doc's current text and the new text and apply it via `hocuspocus.openDirectConnection(docName)`
in one transaction (origin is a `LocalTransactionOrigin`, so the persistence `update` listener still logs it).
Never replace the `Y.Doc`. Collaborators' cursors and undo stacks survive.

## 5. Compile

Unchanged contract with the worker. Binary files are now real: the orchestrator already uploads blobs the worker lacks.
Compile is allowed for owner/editor only (already true). No other changes in M1.

## 6. Production serving

`apps/server` serves the built SPA (`apps/web/dist`, path from `WEB_DIST_DIR`) for all non-`/api`, non-`/collab`
GET requests (SPA fallback to `index.html`), with `Cache-Control: no-cache` for `index.html` and long-lived caching for
hashed assets, a strict CSP for the app shell, and `.mjs` served as `text/javascript`.

```sql
ALTER TABLE users ADD COLUMN is_admin INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN disabled_at INTEGER;
ALTER TABLE projects ADD COLUMN deleted_at INTEGER;
ALTER TABLE projects ADD COLUMN updated_at INTEGER NOT NULL DEFAULT 0;

ALTER TABLE files ADD COLUMN updated_at INTEGER NOT NULL DEFAULT 0;
ALTER TABLE sessions ADD COLUMN last_seen_at INTEGER NOT NULL DEFAULT 0;
CREATE TABLE instance_settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE invites (
  id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  token_hash TEXT NOT NULL UNIQUE, role TEXT NOT NULL CHECK (role IN ('editor','viewer')),
  created_by TEXT NOT NULL REFERENCES users(id), created_at INTEGER NOT NULL, expires_at INTEGER NOT NULL,
  max_uses INTEGER, uses INTEGER NOT NULL DEFAULT 0, revoked_at INTEGER);
CREATE TABLE blobs (hash TEXT PRIMARY KEY, size INTEGER NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE audit_log (id INTEGER PRIMARY KEY AUTOINCREMENT, actor_id TEXT, project_id TEXT,
  action TEXT NOT NULL, detail_json TEXT, at INTEGER NOT NULL);
```

Audit-log entries for: signup, login success/failure, logout-all (password change), admin user changes,
settings changes, member add/role change/remove/transfer, invite create/revoke/accept, project create/delete, file delete.

## 7b. Operations

- **CLI** `apps/server/src/cli.ts` (`npm run cli -w @ligature/server -- <cmd>`; in Docker `ligature <cmd>`):
  - `backup <dir>`: SQLite online backup (`db.backup()`) of `app.db` + copy of `blobs/` into a new timestamped directory; prints the path.
  - `reset-password <username>`: reads the new password from stdin (no echo when a TTY), deletes the user's sessions.
  - `create-admin <username>`: creates an admin (password from stdin) — for `closed` instances and recovery.
- **CI** (`.github/workflows/ci.yml`, GitHub Actions, ubuntu-latest, Node 24):
  1. `test`: `npm ci`, install `latexmk` + a small TeX Live from apt, typecheck all packages, `npm test`, `vite build`.
  2. `sandbox`: on Linux **as root**, run the compiler test suite with `SANDBOX=uid` (tests that need root/Linux are
     skipped elsewhere and **must run here**), plus the malicious-TeX corpus (`apps/compiler/test/corpus/`).
  3. `docker`: build `docker/Dockerfile.app` and `docker/Dockerfile.compiler` (the medium TeX Live variant to keep CI fast),
     start the compose stack, wait for health, compile a sample project through the real API, check a PDF comes back.

## 8. Malicious-TeX corpus (must fail safely)

Each case is a project (files + main file) plus an assertion. Run with the `uid` sandbox on Linux as root.
"Fails safely" = the worker stays up, nothing outside the project directory is read or written, no network,
the compile ends (status `failure`/`timeout`/`success` as specified) within its timeout, and other projects are unaffected.

1. `\input{/etc/passwd}` and `\openin` of `/etc/passwd` → content does not appear in the log or PDF text.
2. `\input{../<other project id>/src/main.tex}` (another project's build dir) → refused.
3. `\immediate\write18{touch /tmp/pwned}` → no file created (shell escape off).
4. `\directlua{os.execute("touch /tmp/pwned")}`, `io.popen`, `io.open("/etc/passwd")`, `io.open("/builds/<other>/...")` with lualatex → no effect / no content leak.
5. `\openout` to `../../evil.tex`, `/tmp/evil`, and an absolute path into another project → refused.
6. Infinite loop (`\def\x{\x}\x`) → `timeout`, process group killed, no stray processes.
7. Log flood (millions of `\message`) → log capped, worker healthy.
8. Huge output (a PDF beyond the cap) → refused, worker healthy.
9. Fork bomb via lua (`os.execute` disabled, but also `io.popen` loop) and `\loop` writing many files → quota/limits stop it.
10. A symlink planted in `out/` by one build (via lua) pointing at `/etc/shadow` or the worker's blob cache → next build and output fetch do not follow it.
11. `latexmkrc` in the project → not executed (`-norc`).
12. Main file named `-shell-escape.tex` / with shell metacharacters → rejected before spawning.
